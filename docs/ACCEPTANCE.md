## 浏览器闭环

`tests/e2e/store.spec.ts` 执行四个串行场景：

1. 游客权限拒绝 → 手机号识别 → 投稿公开仓库 → 原生队列处理 → 市场自动出现 → 收藏及刷新持久化 → README 原文与安全相对链接/图片 → 两个架构 IPK 分别下载到本地 → 核对文件名、实际字节 SHA-256 与统计 → 公开详情只含公开审核字段（断言响应不出现内部依据）。
2. Studio 实际密码登录 → 总览 → AI 配置连通性测试 → 下载源与测试目标选择 → 账号安全面板 → 插件管理（操作原因、更多操作菜单、下架确认弹窗）→ 下架阻止详情和旧下载地址 → 显式恢复触发重新审核 → 审计日志 → 退出失效。
3. 设计系统、主题与键盘可用性：断言设计令牌已生效（主色、圆角、正文字号、头部高度、搜索框圆角、按钮高度）、`/` 快捷键聚焦搜索并写入查询参数、Tab 焦点环可见（元素自身或容器的 outline / 主色 ring）、深色主题切换并在刷新后持久化、浅色主题还原。
4. 375、768、1280、1440 像素宽度 × 6 条路由（市场、详情、登录、投稿、个人中心、Studio）无水平溢出；并在浅色与深色下生成市场/详情/登录/投稿/个人中心截图，以及 Studio 六个面板的桌面截图与两个面板的手机截图。

浏览器没有拦截业务 API。测试运行真实构建的 Worker、隔离 D1、实际迁移及本地原生 Queues；仅向外部 GitHub/AI 的请求在 Miniflare 出站边界替换为无害固定响应。测试控制入口只由测试服务器提供，不打入生产 Worker。AI 的 allow 是隔离服务响应，仍经过生产 JSON 校验、来源复核和发布事务。

本轮浏览器验收同时记录设计系统与键盘可用性检查，写入 [frontend-qa.json](evidence/frontend-qa.json)；该文件由同一次真实浏览器运行生成，与全链路验收使用同一构建产物。

## 已发现并修复的问题

测试过程中修复了原生 Workers 不接受的 DNS 请求 redirect 选项、审核配置变化时的发布竞态、第三方源测试证明的读取格式、收藏状态刷新、Markdown 恶意输入净化验证，以及删除后迟到任务重新保存材料的问题。最终结果来自修复后重跑的完整命令，不是早期失败输出。

生产构建会去掉 Vite 为本地预览复制的 `.dev.vars`，并扫描实际开发密钥值与测试入口哨兵；检测到泄漏则使构建失败，不输出敏感内容。

## 已知边界

首版自报手机号只用于识别，不验证号码归属或小店绑定。支持的 IPK 封装/压缩格式、材料预算和资源上限见 [DECISIONS.md](DECISIONS.md)；超出支持范围为检查未完成。AI 静态审核不能等同安全认证，二进制不运行动态沙箱或病毒引擎。

下载不存镜像。审核时完整计算 SHA-256，下载时重新核验官方资产身份；纯流式分发不能在发出首字节前重新计算整包哈希，第三方源只能在明确测试和信任后启用。下载数表示成功开始的尝试，不表示完整下载或安装人数。

后续配置与外部验收步骤见 [DEPLOYMENT.md](DEPLOYMENT.md)。旧 `boss-message-box-v1` 未修改；未创建远程仓库、推送、部署生产、执行生产迁移、修改 DNS 或购买服务。
