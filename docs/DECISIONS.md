# 工程决策

## 身份与数据

普通身份由独立认证 Worker 管理，商店 `users` 中的 SSO 行只保留全局 UUID 的业务引用。本站使用 host-only、Secure、HttpOnly、SameSite=Lax Cookie，受保护请求实时检查中央会话；资料更新失败不撤销有效登录。完整协议见[统一登录](shared-auth.md)。

旧手机号档案保留原关联，只有人工核实后才能绑定全局用户；不能用相同自报手机号推断同一人。`SSO_ENABLED=false` 保留旧识别流程供隔离开发使用，不作为生产身份验证。

管理员来自 `ADMIN_AUTH_DB`，会话仍在商店 DB 保存，最长 12 小时。每次请求检查共享账号及验证记录版本；只读共享库，不复活默认密码，不把有赞身份升级为管理员。写接口校验 Origin，公开接口不返回内部审核依据或凭据。

## 人工审核与版本

`REVIEW_MODE` 缺省即人工审核。队列整理 GitHub 或直传材料，冻结候选；批准决定绑定 revision、文件身份和管理员会话，原子发布。新候选未批准时保留旧批准版本。相同已批准材料可复用决定，变化材料必须重新审核。

GitHub README 固定到读取时默认分支的 commit/path；Release 源码固定到 tag 对应 commit，两者分别保存。直传使用作者教程。商店不执行作者代码、安装脚本或构建命令。

历史版本只列曾批准且符合当前发布模式的快照。当前插件下架或停用后，历史版本也不可下载。R2 清理保留当前候选和全部批准版本；早期已清理的文件不能仅靠数据库快照恢复。

文件摘要保留在后端与接口中用于一致性校验，页面不展示 SHA-256。下载界面只保留版本、文件名、架构、大小和下载操作。

## 资源限制

| 范围 | 默认或上限 |
| --- | --- |
| 单个直传 IPK | 32 MiB；`MAX_IPK_BYTES` 可降低 |
| GitHub 单 IPK | 默认 32 MiB，配置上限 64 MiB |
| 每 Release 的 IPK | 最多 8 个；附件列表超过读取范围时不视为完整 |
| 单包解包 | 累计 32 MiB，2000 个条目，路径深度 16 |
| 包内文本 | 累计 512 KiB，单文件 128 KiB |
| README | 128 KiB UTF-8 |
| 直传存储 | 每账号 128 MiB；管理员投稿合并计算 |
| 任务领取 | 最多 4 次，锁 10 分钟 |
| 队列 | 批量 1，并发 2，额外重试 3 次，配置死信队列 |
| 扫描与任务恢复 | 每批 25 / 50 项 |

归档支持 `ar` 或 `tar.gz` 外封装、`debian-binary 2.0` 和内部 tar/gzip；不支持的 xz/zstd、PAX/GNU 扩展、危险路径、损坏数据或资源超限均停止处理。提高压缩包大小限制不会自动提高解包预算。

上传先写随机不可变对象，再在 D1 事务内校验配额与任务归属；失败清理对象。未被候选或批准快照引用的旧上传、孤立对象满一天后由 Cron 分批回收。直传记录使用唯一负数占位满足旧 repository_id 约束，来源必须按 `source_kind` 分流，不能把此值发送给 GitHub。

## 下载与任务恢复

下载只接受站内插件、快照和附件 ID，不接受任意目标 URL。GitHub 包重新核验官方 repository/release/asset 身份后流式转发；直传核对私有对象和批准快照。支持 HEAD、单 Range、取消连接和限流。纯流式下载不能在首字节发出前重新计算整包摘要。

第三方下载源仅在管理员信任并完成配置对应的测试后启用。HTTPS、主机白名单、公共 DNS 与逐跳重定向校验用于限制目标；GitHub Token 只发给 GitHub API。

下载数统计成功开始的尝试，10 分钟内同身份、插件和附件去重；HEAD 和失败不计数，不代表安装人数。收藏以用户与插件唯一约束保证幂等。

任务持久化后入队，失败保留可恢复状态；revision 和锁令牌防止重复或迟到任务覆盖新决定。GitHub 临时错误不下架；疑似仓库缺失需官方身份复查及跨至少一小时的重复证据。

## 保留的自动引擎

这些模块供开发和后续恢复使用，当前人工审核不调用 AI 或 Cloudmersive。

| 配置 | 行为 |
| --- | --- |
| `REVIEW_MODE=manual` 或未配置 | 必须人工批准，`REVIEW_ENABLED` 不改变此规则 |
| `REVIEW_MODE=automatic` 且 `REVIEW_ENABLED=true` | 运行保留的自动审核管道 |
| `REVIEW_MODE=automatic` 且未启用 `REVIEW_ENABLED` | 历史免审模式；整理后直接发布，不符合当前上架要求 |

自动引擎代码和测试保留，但不能把单改 `REVIEW_ENABLED` 当作生产恢复方案。切换前须重新确认发布策略、既有快照与审核配置。

- AI 使用兼容 Chat Completions 的接口，Studio 保存加密 Key 与规则。输出严格限制为 `allow/reject/uncertain` 和公开/内部理由；超时、无效响应、缺配置和材料不足不会批准。
- 默认输入预算 100000 字符、输出 1500 token、超时 45000 ms、额外重试 2 次；每日任务预算由 `DAILY_AI_BUDGET` 控制。设置变化使审核缓存版本变化。
- GitHub 自动审核有界读取源码与构建材料；最多 2000 个树条目、128 个源码 blob、累计 1 MiB，单文件 256 KiB。二进制只记录清单与摘要，不向模型发送 Base64。
- 直传自动审核先将包内普通文件重组为 TAR，再调用 Cloudmersive advanced file API；不要求提供对应 GitHub 源码。Key 使用 `CLOUDMERSIVE_API_KEY` Secret。
- `CLOUDMERSIVE_MAX_SCAN_BYTES` 默认 3500000 字节，上限 64 MiB，限制的是重组后未压缩 TAR，不是原 IPK。超限、不能检查和异常结果不继续发布。真实套餐额度由部署者核实。
- 旧 `/manual-publish` 接口在当前人工模式下仅批准已准备的候选，不能绕过待审记录；旧免审快照不自动获得人工批准标记。

## 前端与许可

Vue SPA 与同源 Worker API 共用部署。Markdown 经 DOMPurify 和 URL 校验；作者内容不能执行。浅深主题、键盘焦点、触控目标和窄屏布局由组件与集中样式维护，不引入第二套 UI 框架。

不做代作者安装、构建或设备管理。独立详情 URL、metadata、robots/sitemap 提供基础索引信息；SPA 不保证搜索引擎完整收录。GPL 与对应源码要求见[上游记录](UPSTREAM.md)、[第三方声明](../THIRD_PARTY_NOTICES.md)和 [LICENSE](../LICENSE)。
