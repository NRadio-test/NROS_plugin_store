# V1 工程决策与边界

本文件对应 2026-09-10 这次本地实现。具体需求以 `REQUIREMENTS.md`（来自父目录完整提示词） 为准；这里只记录未细化问题的工程默认值与实际边界，不降低验收要求。

## 身份与权限

手机号只做自报识别，不接短信、订单或会员系统。内地 11 位号自动补 `+86`；去掉空格、括号和连字符，`00` 转 `+`；其他地区必须使用国际区号，并通过 8–15 位数字等格式检查。保存随机 user_id、HMAC-SHA256 手机号索引与必要掩码，不持久保存完整可读手机号。

会话为 32 字节随机 token，D1 只保存 token 哈希。普通会话 30 天，管理员 12 小时；生产使用 `__Host-` 独立 Cookie、Secure、HttpOnly、SameSite=Lax，不设置父域 Domain。所有写请求做 Origin/来源校验；手机号或客户端 user_id 不是凭证。号码冒用风险仍存在，限流不能消除。

普通提交者与 GitHub 作者分开，重复 repository ID 不转移提交归属。普通用户只能刷新自己的原仓库。管理员权限一致，不做角色分级。

旧站只读参考了当前认证代码格式；安全导入接受 `pbkdf2-sha256$iterations$salt$hash` 的当前验证资料，保留算法、盐和迭代参数。命令限制导出字段与文件权限，并隐藏验证当前密码；拒绝历史公开默认验证值/初始化账号。新设密码使用随机盐和 PBKDF2-SHA256。导入或设密使本商店已有管理员会话失效，不复制旧会话、业务数据或 Secrets；不承诺两站改密同步。当前有效管理员凭据尚未导入。

## 展示快照、源码快照和原子发布

`readmeCommit` / `readmePath` 来自默认分支的实际 README；`sourceCommit` 来自最新正式 Release tag 的实际 commit（支持有限深度 annotated tag 解析）。两者独立保存，README 不替换成 Release 正文、AI 摘要或包内说明。

description/README/Release/asset 等组成候选快照；技术检查后提交给 AI，发布前重新核验官方源。新内容通过前保持旧批准快照；若旧资产失效，下载端及时拒绝。不提供历史版本选择。任务 revision、锁 token、锁有效期、当前审核设置版本和管理员停用标记共同限定最终发布，不能靠旧结果、重复任务或再次投稿恢复被停用插件。

同一快照与审核规则版本复用审核结果；管理员“重审”显式生成新审核版本标记。修改 AI 设置使审核规则版本改变；发布中的旧配置结果不能悄悄覆盖新设置。无变化不会每天再次消耗 AI 审核配额，但仍需要向 GitHub 条件核验与验证资产；首版未实现“完全不读源码/IPK”的网络成本优化。

源码按 Git tree/blob 有界逐个读取，不下载源码 ZIP、不执行文件。图片、媒体、字体和仓库归档不作为可读源码扫描，记录路径及 Git blob；关键源码不能读为 UTF-8、外部子模块、未读取 LFS 或没有可读源码/构建材料时未完成。

## IPK 支持范围与 AI 边界

支持 `ar` 或 `tar.gz` 外封装，`debian-binary 2.0`，内部 control/data 的标准/ustar tar 或 gzip。检查重复路径、穿越、绝对路径、链接逃逸、畸形头部/校验和、超限与隐藏尾部。PAX/GNU 扩展、xz/zstd、特殊设备、包内嵌套归档等目前未支持，进入未完成。

所有安装卸载/包内文本脚本只静态读取。二进制记录路径、大小与 SHA-256，不发送 Base64 给模型；存在二进制时要求 Release 中有对应构建配置，AI 还要判断源码关联。此关联不是可复现构建证明，也不是病毒扫描。普通联网、shell、系统服务等行为不能仅按关键词拒绝。

AI 使用 Chat Completions：规范化后缀而不擅自重复 `/v1`；默认只发送兼容字段，提供商支持时可启用 JSON schema。严格只接受 verdict/publicReason/internalReason 三个字段，verdict 为 allow/reject/uncertain。结构化输出关闭时仍严格验证返回 JSON；拒答、截断、未知字段、空结果、超时或错误不通过。模型没有 shell、网络、数据库或凭据工具；提示注入材料只作为不可信数据。

API Key 用 AES-GCM 服务端加密，主密钥在 Workers Secrets。Studio 返回掩码，手机号/会话/管理员资料不进入审核材料。连通性测试可能消耗提供商 token，测试结果不会发布插件。按任务计数的每日预算不等于提供商精确 token/费用上限，重试及 Studio 连通性测试有各自限制。

## 同步、异常与恢复

Cron `0 4,16 * * *` 对应北京时间 12:00、24:00，仅表示扫描开始时间。GitHub API 使用 token（已配置时）和 ETag 条件请求。队列只带 taskId/扫描游标，不携带整份归档。数据库已写入但入队失败的任务保持待恢复状态，由后续恢复检查重新入队。

官方源 401/403/429/5xx/超时为临时异常，不能因代理 404 批量下架。仓库疑似不可见时按稳定 repository ID 复查并匿名重查，以排除 token 权限和改名影响；至少两轮、间隔一小时的官方缺失证据才判不可公开访问。Release/tag/blob 缺失会记录材料不完整，不混同仓库删除。

删除采用市场移除、停止下载和保留最少墓碑/提交原因。管理员下架设置阻止自动恢复；显式恢复清除批准快照并重新审核。不修改作者 GitHub 仓库。

入队恢复主要由定时入口启动；若本地没有调度事件，需触发本地调度/手动检查或在 Studio 重试。首版不引入 Redis、额外常驻服务或运营分析面板。

## 下载来源、安全与统计口径

默认仅 GitHub 官方 API 资产源。下载请求只含站内 plugin/asset ID，不接受来源、目标 URL 或镜像 query。取已审核固定 Release/asset 后核验官方仓库身份、tag commit、附件 ID/大小/更新时间/摘要，最后再检查批准状态，防止绕过未审核的新版本。

服务端验证 HTTPS、主机、DNS 地址与有限重定向。非官方主机先向固定 DoH 服务预检 A/AAAA，但随后实际 fetch 由 Workers 网络层再次解析，首版没有固定目标 IP 的连接能力，不能宣称彻底消除所有 DNS 重绑定/解析时差风险；第三方主机仍须管理员明确信任。GitHub token 只发给预期 GitHub API 主机，不携带用户 Cookie/Authorization 到上游。HTML/JSON 错误页不会伪装成 IPK；支持 HEAD、单 Range/206/416、流长度约束与取消。

第三方来源必须显式信任、以停用状态保存、用具体批准资产测试成功，再启用；修改影响测试指纹的配置后须重测。测试读取最多前 4096 字节验证格式/范围响应，不是整包逐字节验证。官方审核阶段保存 SHA-256，发布前能获取官方摘要就比较，缺少时重新受限读取哈希。下载阶段纯流式转发不预读整包，不声称任意镜像在首字节之前已经验证全部内容。

IPK 不存 D1 Blob/R2/持久缓存。D1 只保存必要公开材料/摘要与状态；权限页面和 API 不共享缓存。第三方源、Workers Paid 或 Cloudflare 都不自动保证大陆可达性，不默认拥有大陆节点；真实网络测试见部署指南，当前未测速。

收藏唯一约束是 user_id + plugin_id，表示当前收藏的识别档案数，不是已核验自然人数。下载次数在上游成功开始、前缀有效且批准状态仍有效时计数；HEAD、失败不计数，同身份的短期重试/Range 去重。流后续中断仍是一条“已开始尝试”，不等于完整下载成功、安装人数或 GitHub 原生统计。

## 界面、许可与已知限制

复用 AstrBot 独立市场的适用 Vue 组件逻辑，保留 GPL-3.0 与对应源码说明；不复制原站安装、Issue 投稿、原 API 或主程序。官网描述与 README 为作者内容，前端做 DOMPurify 允许列表和 URL 验证；外部图片仅允许 GitHub 内容域名，其他图片提供说明与仓库入口，避免图片成为内网请求通道。

界面先完成简体中文、浅深主题、手机/平板/桌面和必要异步状态。详情 SEO 为独立 URL、metadata、robots、sitemap，不引入 SSR，不保证 SPA 全量收录。Studio 插件列表已改为服务端分页与状态筛选（默认每页 20，可 10–100），搜索关键词在服务端转义并加 `ESCAPE`；审核任务与操作日志仍按最近 200 / 100 条读取后在界面分页，大规模历史归档可后续扩展，首版未引入搜索集群。

界面视觉于第二轮整体重做：集中式设计令牌 + 自建组件库，不使用第二套 UI 框架，也不引入网络字体或图标包。深色主题的填充色与文字色分离为两组令牌，以保证按钮提亮时链接仍然可读；34 组颜色对比度由 `scripts/check-contrast.mjs` 在 `pnpm run check` 中强制校验。危险操作确认由自建模态替换浏览器原生 `confirm`，与其余界面保持一致并可被自动化验证。市场的排序（最近更新 / 最受欢迎 / 下载最多）是简单确定的白名单排序，不是推荐系统。

缺少真实管理员验证数据、AI Key 和 Cloudflare 配置时保持真实适配器与隔离测试，不植入固定 allow 或假管理员。当前真实外部 AI、GitHub token、Cloudflare 线上运行、当前管理员安全导入及大陆网络表现未联调；本地测试通过与外部部署成功分开报告。
