## 七、真实自动审核与 AI 配置

新投稿、新 Release 及有实质变化的审核材料自动审核，通过后自动上架，不增加日常人工审批。不因 Star 少、功能简单或说明朴素拒绝，重点识别垃圾、欺骗和恶意行为。

实现持久化异步流程：创建任务 → 读取 GitHub 快照 → 受限静态解析 IPK/源码 → AI 审核 → 验证输出与快照 → 原子发布。提交接口返回任务 ID，关闭页面不丢任务。

必须真实获取材料，不得只把仓库 URL 发给模型，也不能只看 README 就声称做过代码审核。材料至少覆盖 description、README、相关源码、依赖/构建配置、IPK 文件清单、控制信息、安装卸载脚本和包内可读脚本。

- 对源码和归档采取明确预算、有界读取、分批处理；记录覆盖范围与跳过原因。关键材料不全、解析不支持或超限时标为未完成，不能静默截断后宣称完整检查通过。
- 实现可在 Workers 运行的受限 IPK 静态解析，使用有代表性的实际格式测试样例；明确支持的封装/压缩变体。不执行仓库代码、安装脚本、二进制或 shell 命令。
- 检查路径穿越、异常链接、畸形归档、压缩炸弹及资源超限。不要把整个仓库/解包数据无上限读入内存或序列化进队列消息。
- 不能仅因出现 shell、curl、网络连接、系统服务或防火墙修改而判恶意；结合用途、授权和行为。
- 二进制存在本身不等于恶意；不得把二进制 Base64 发给聊天模型就宣称完成病毒扫描。记录二进制与源码关联、扫描覆盖等边界；无法取得关键证据时进入未完成。
- 显示“通过自动审核”等准确措辞，不宣传“保证无病毒”。首版不追加动态沙箱、可复现构建或第三方商业杀毒服务作为隐藏前提。

AI 使用 OpenAI 兼容的 Chat Completions 协议，首版一个提供商。Studio 可配置 Base URL、模型、API Key、超时、最大重试、输入输出预算及审核规则，并提供连通性测试。

- 正确规范化 Base URL 与 /chat/completions 路径，避免重复 /v1；参数与提供商能力相匹配，不强加所有兼容服务都不一定支持的字段。
- 支持结构化输出时可使用；否则请求 JSON 并在服务端严格验证枚举、必填项、长度和未知字段。
- 结果分为 allow、reject、uncertain。保存面向用户的简短理由与内部检查依据；不要把完整内部材料泄露到个人页。
- 只有明确 allow、技术检查完成、快照有效且未被管理员停用时才能发布。
- API 超时、429/5xx、余额不足、拒答、空结果或格式错误均不能默认通过。有限退避重试，耗尽后保留失败状态和 Studio 重试入口。
- 缺少 AI 配置时停在待配置/待审核，不能自动允许全部插件。
- README、源码与模型输出都是不可信资料。模型没有 shell、数据库修改或凭据读取权限；防提示注入，输出只作为受约束审核结果处理。
- 仅把必要公开仓库材料送往 AI；不发送手机号、会话、管理员资料、系统密钥。API Key 服务端加密保存，主密钥放 Workers Secrets，读取设置只返回掩码。
- 设置任务指纹、提交/刷新冷却、每日审核预算与有限重试，复用相同快照的有效结果。不能每天把没变化的插件重新发给 AI。

## 八、定时更新、异常与删除

按北京时间每天 12:00 和 24:00 启动检查，Cloudflare UTC Cron 配置为 0 4,16 * * *。这是扫描启动时间，不要求所有插件整点同时完成。

Cron 分页分批产生队列任务，使用 GitHub 认证 API、条件请求和有界并发；普通访客打开页面不实时触发整套 GitHub/AI 检查。作者手动刷新走相同管道，不绕过审核。

- 内容没变仅更新检查时间；新 Release/实质变化创建候选审核，通过后才切换。
- 403/429、超时、5xx 记录临时错误，不删除插件；单次 404 不认定删库。
- 仓库疑似删除或转私有时，向 GitHub 官方源核实并排除重命名、转移、凭据失效等原因；不可因镜像站 404 批量下架。

- 队列按可能重复、乱序和崩溃重试设计。使用 D1 持久任务、revision/幂等键、过期锁、重试/死信及可恢复入队机制。旧任务不能覆盖新版本；发布前再次核验候选 revision、来源资产和管理员状态。

## 九、Worker 下载转发与下载源

使用站内 plugin/asset 标识访问下载入口。下载不是跳转 GitHub 网页，而是 Worker 取得已批准的 Release IPK 后，以附件形式流式返回浏览器，最终下载到用户本地。

- 服务端从 D1 解析已批准的资产，不接受用户传任意目标网址，不提供开放代理。
- 下载前检查插件有效状态、当前批准版本与资产身份；不能把 /latest 或可变分支直接作为未经核验的下载来源。
- 正确设置 Content-Disposition、下载文件名、Content-Type 和防 MIME 嗅探等头部；不把 HTML/JSON 错误页伪装成 IPK。
- 处理 HEAD、合理单 Range/206/416、上游超时、取消连接、文件大小上限与错误反馈；不宣称下载已完整成功。
- 下载路径必须流式处理，不先整体读入内存；不把包写入 R2、D1 Blob 或持久缓存。审核阶段与下载阶段的资源处理分开。
- 公共请求不能直接指定镜像。所有 HTTPS 主机、URL 模板、重定向和目标均验证，禁止内网/本地/元数据地址、凭据型 URL 和无限跳转。
- GitHub token 只发送给预期 GitHub API 主机，不能随重定向泄漏到镜像或任意资产主机。不要转发用户 Cookie、Authorization 给上游。
- 下载权限、个人页和 Studio 不使用共享缓存。静态资源可以缓存，目录/README 缓存必须配合上架、下架和更新失效。

Studio 提供下载源名称、地址规则、允许主机、启用状态、优先级、超时及针对具体资产的测试入口。默认只启用 GitHub 官方源；第三方源由管理员配置、测试并明确信任后启用，不捏造清华/阿里/腾讯对任意仓库都有镜像。

保存审核时的官方资产摘要，能核验时核验，并可向用户展示 SHA-256。说明纯流式分发不能在发出任何字节之前完成整份文件哈希，不能伪称任意第三方镜像已逐字节预验证。切换下载源不得切换版本或附件。没有可用源时清楚报错。

不承诺 Workers Paid 自动改善大陆网络，也不默认具备中国大陆节点。部署文档列出真实大陆网络测试方法，不虚构测速结果。

## 十一、Studio 与旧管理员账号复用

所有管理员权限一致，不建设角色分级。后台包括插件列表与搜索、提交仓库、查看状态及审核理由、手动同步、重审、下架、删除、显式恢复流程、AI 设置、下载源设置和基础操作日志。管理员提交也走审核，不悄悄绕过。

只读检查老板留言箱当前认证实现和可访问的现有账号验证数据，按真实格式复用当前有效管理员账号/密码哈希、盐和参数。不要猜密码，不恢复旧默认密码，不复制旧会话、不复制无关业务数据或旧系统真实 Secrets。

新商店与旧站使用独立 Cookie、会话和鉴权范围，不共享父域管理员 Cookie。一次导入不等于单点登录，也不保证两站后续改密自动同步。

如果当前账号验证数据不可访问，完成安全导入/设密命令及文档，明确标记“等待导入当前管理员凭据”；不要伪造完成或用公开默认口令应付。不能把哈希、明文密码、密钥输出到文档和日志。

管理员敏感操作必须服务端鉴权、来源/CSRF 校验并留审计记录。删除/下架不修改 GitHub 仓库本身。保留退出登录；密码管理如实现，应符合真实导入算法并使旧会话失效。

## 十二、工程、数据和安全底线

D1 至少表达用户/会话、插件与提交、Release 快照与资产、收藏、审核任务/结果、管理员/会话、下载聚合、设置、审计记录。可以合理合表，但不能混淆普通用户和管理员身份，也不能把公开插件状态与候选审核状态压成一个错误布尔值。

- 使用迁移、索引、外键、唯一约束和 D1 支持的原子更新方式；测试并发收藏、重复任务与发布竞态。
- 数据库写入成功但入队失败时可恢复；页面不能显示成功后实际上永远无任务。
- Secrets、.dev.vars、导入凭据、真实数据库导出、运行日志排除出 Git；提供无真实值的 .dev.vars.example。
- 所有写操作做输入校验、必要的鉴权、CSRF/Origin 校验、速率限制；敏感配置只在服务端。
- AI Base URL、下载源测试、README 图片处理等同样不能成为任意内网请求工具。
- 生产环境禁用 mock 审核/固定 allow/假管理员。模拟响应只允许在明确隔离的测试或开发环境，并能验证生产构建不走假实现。
- 控制队列 batch、并发、源码大小、解压预算、CPU 与请求超时；按 Workers 运行时限制实测。不能用 Node.js 本地成功替代 Cloudflare 兼容性验证。

## 十四、必须验证的场景

1. 游客浏览/搜索/详情/下载正常；提交与收藏必须有识别会话，普通会话无法访问管理员接口。
2. 首页无 README，详情正确显示 GitHub 仓库 README、相对图片/链接；无 AI 改写、无以 Release 正文或源码 ZIP 替代。
3. 公开仓库 → 正式 Release → 真实 IPK 解析 → AI 结果校验 → 自动上架闭环。缺少 IPK 明确提示；多 IPK 可选且内容/文件名正确。
4. README XSS、恶意外链、提示注入、错误模型 JSON、超时、限流和缺少 AI 配置不导致执行恶意内容或默认上架。
5. 畸形 IPK、路径穿越、压缩炸弹、资源超限、不支持格式与核心材料缺失有受控结果，不误写完整审核通过。
6. 新版本审核前无法绕过；审核期间 asset 替换、tag 移动、乱序/重复队列和管理员删除不会发布错误产物或复活插件。
7. 北京时间两次 Cron、手动刷新、任务去重、入队失败恢复与有限重试可验证。
8. GitHub 暂时异常和单次 404 不误删；确认仓库不可公开访问后市场移除、后续下载禁止、个人页保留下架状态。
9. 代理拒绝任意 URL、内网、未批准 asset、恶意重定向；不泄漏 token，不下载 HTML 错误页。HEAD/Range/取消连接及统计去重正确。
10. 收藏/取消收藏重复与并发一致；用户不能直接改统计数字，内部敏感信息不出现在公开接口。
11. 管理员导入兼容真实认证格式，旧默认密码不复活；数据不可得时如实记录，生产 mock 不可启用。
12. 手机、平板、桌面页面无关键溢出或阻挡操作；提供浏览器端验收证据和实际命令结果。

使用本地隔离 fixture 覆盖故障与恶意样例，不向第三方仓库投稿或上传测试文件。使用无害 IPK 样例验证下载、哈希和格式。真实 GitHub/AI/Cloudflare 联调仅在已有授权配置下进行；无配置时区分“测试通过”与“真实外部联调尚未完成”。
