# 全部人工审核

当前策略：`REVIEW_MODE=manual`，自动审核和 Cloudmersive 查毒不参与上架。没有配置审核模式时也默认人工审核；仅修改 `REVIEW_ENABLED` 不能绕过人工审核。原自动引擎代码、设置及服务端凭据保留。

## 作者与管理员流程

1. 作者或管理员填写资料后上传 IPK，或者提交 GitHub 仓库。
2. 原队列整理真实安装包，验证格式、大小和文件一致性，将展示资料与附件冻结为待审快照。此时市场、公开详情和公开下载都不可获取新版本。
3. Studio 默认打开“审核收件箱”。管理员查看简介、使用说明及具体版本，下载待审安装包；待审文件仅通过管理员接口下载，不计入市场下载数。
4. “通过并上架”保存审核人、时间、结论和审计，发布当前冻结的快照；“退回修改”要求至少 5 字的具体原因，并向作者反馈。内部备注只在后台保存。
5. 作者在个人中心按“等待审核 / 需要修改 / 已上架”筛选，修改资料或上传新版本后重新送审。审核期间已有人工批准的旧版本继续展示和下载。

审核决定绑定候选 revision，重复或并发处理只能成功一次；审核期间文件、版本或管理员会话变化时拒绝发布。Cron 不反复替换待审或已退回候选。GitHub 同步取得完全一致的已批准内容时沿用原批准；不同内容仍需人工审核。

人工批准表示允许收录，不表示已完成病毒扫描。公共详情明确显示“人工审核通过”。管理员投稿也没有免审上架入口；旧 `/manual-publish` API 在人工模式下只可批准已经准备好的待审候选，不能直接读取新文件并绕过待审记录。

## 旧作品迁移

`migrations/0004_manual_review.sql` 将所有已有未停用的上架作品转为待审，包括曾自动审核、免审或旧手动上架的作品。原快照成为待审候选，文件、上传对象、用户、收藏、投稿与统计保留。管理员重新批准后恢复市场展示。

新版本只认可 `publicationMode=human-reviewed` 的公开快照。即使旧数据仍标记 `published`，没有当前人工批准标记也不能进入市场或公开下载。不能在上线时跳过迁移：这会使旧作品不公开但尚未进入审核收件箱。

备份、迁移顺序及部署命令见[部署说明](DEPLOYMENT.md)。迁移只应用于商店 `DB`，不应用于留言箱或认证服务数据库。

## 验证

`tests/integration/manual-review.test.ts` 覆盖各类投稿、公开下载隔离、候选下载权限、退回、版本替换、并发、权限失效和旧快照阻断。浏览器流程见 `tests/e2e/`；自动引擎测试使用显式 `REVIEW_MODE=automatic` 的隔离环境。

上线后确认：管理员和普通用户投稿均先待审；新版本未批准时不能公开；退回原因对作者可见；已有批准版本继续下载；迁移后的旧作品进入收件箱；普通有赞用户无审核权限。完整检查清单见[验收](ACCEPTANCE.md)。
