# 本次更新：人工审核、UX 和 NRadio Logo

本指南用于更新已有的 `nros-plugin-store` Worker 和 `plugin.zdwifi.com`。配置以当前 `wrangler.jsonc` 为准；不用新建数据库、R2 桶、有赞应用或回调。本次 Logo 采用用户提供的透明 PNG，原图片内容不改动。

## 迁移影响

这次需要插件业务库的 `0004_manual_review.sql`。所有已有且未停用的上架作品会进入人工审核，市场暂时不展示；管理员通过后恢复。原安装包、上传对象、快照、账号、收藏、投稿关联和统计保留。

只对 `plugin-store`（本站绑定 `DB`）执行下面的迁移。不要迁移 `boss-message-box` / `ADMIN_AUTH_DB`，也不要迁移 UV 的统一账号数据库。本站本次更新不改有赞登录入口和管理员权限。

Logo 和 UX 本身不需要数据库迁移；0004 用于之前确认的全部人工审核要求。

## 1. 准备和构建

```sh
cd /Users/dawn/Personal/NRadio/Github/plugin_store
source "$HOME/.nvm/nvm.sh"
nvm use
pnpm install --frozen-lockfile
pnpm run build
```

先确认构建成功，再开始下面的远程操作。保留既有 Worker Secrets；不要重新生成主密钥或登录凭据，不要把 `.dev.vars`、凭据或备份提交到 Git。当前发布配置应保留 `REVIEW_MODE=manual`、`REVIEW_ENABLED=false`、`SSO_ENABLED=true`。

提交代码用于保存版本；`git commit` 本身不执行数据库迁移或生产发布。若 Cloudflare 已设置推送自动发布，请先完成下面的数据库迁移，再推送触发上线。

## 2. 先备份插件业务库

以下命令由部署者在自己的终端执行，会访问远程 Cloudflare；本次本地修改没有执行它们。

```sh
mkdir -p backups
chmod 700 backups
release_backup="backups/plugin-store-before-manual-$(date +%Y%m%d-%H%M%S).sql"
pnpm exec wrangler d1 export plugin-store --remote --output "$release_backup"
chmod 600 "$release_backup"
```

只有导出成功、备份文件已保存后才继续。该备份是敏感业务数据，不上传到 Git；D1 导出包含元数据，安装包仍保留在原有私有 R2，0004 不改 R2 对象。

## 3. 核对待执行迁移，再应用

```sh
pnpm exec wrangler d1 migrations list plugin-store --remote
```

已有站点应已应用 0001–0003。若待执行列表只包含 `0004_manual_review.sql`，执行：

```sh
pnpm exec wrangler d1 migrations apply plugin-store --remote
pnpm exec wrangler d1 migrations list plugin-store --remote
```

执行时确认目标是 `plugin-store`；最后应不再有待执行迁移。若 0004 已应用且没有待执行项，直接进入部署。若出现 0001、0002、0003 或重复表/列错误，先停下核对迁移记录和当前表结构，不重复直接执行 SQL，也不删除或重建库。

认证失败时先完成 `pnpm exec wrangler login`，然后重新核对待执行列表。任何阶段失败都先解决该阶段，不继续发布。

[Cloudflare 官方迁移说明](https://developers.cloudflare.com/d1/reference/migrations/)：迁移记录保存在 `d1_migrations`，Wrangler 按记录执行未应用文件。

## 4. 部署现有 Worker

迁移成功后连续完成部署，避免长时间停留在迁移后、代码未更新的状态。建议选择短维护时段，期间暂停投稿和后台编辑。

```sh
pnpm exec wrangler deploy
```

此命令使用第一步的 Vite 构建产物，更新现有 `nros-plugin-store`。也可使用项目脚本 `pnpm run deploy`，它会先重新构建再发布。不要用含义不同的裸 `pnpm deploy`。

[Cloudflare Vite 官方部署示例](https://developers.cloudflare.com/workers/vite-plugin/get-started/) 同样采用构建后 `wrangler deploy`。继续使用现有 `plugin.zdwifi.com` 绑定，不另建 Pages 项目。

## 5. 上线核对

1. 打开 `https://plugin.zdwifi.com`，确认新的 NRadio Logo 和界面。
2. 在 `https://plugin.zdwifi.com/studio` 使用原留言箱管理员账号登录，旧作品应出现在审核收件箱。
3. 查看一个旧作品的说明和安装包，点“通过并上架”，确认市场、详情和下载恢复。
4. 提交一个无害 IPK，确认先待审；退回后作者能看见原因；管理员投稿也需审核。
5. 确认收藏、投稿归属和原有有赞统一登录仍正常，普通用户无法审批。

本地 127.0.0.1 预览使用隔离示例数据；迁移和部署不会把这些示例作品上传到生产。
